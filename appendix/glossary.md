# 付録B. 用語早見表

「一言で」だけを先に覚え、詳細は各章で確認してください。

| 用語 | 一言で | 詳しく |
|---|---|---|
| **非同期処理** | あとでやる | 呼び出し元を待たせずに処理する方式 |
| **Job / Task** | 1つの仕事 | 後で実行したい処理の単位。データとして運ばれる |
| **Queue** | 待たせる場所 | Jobを一時的に預かる。基本はFIFO |
| **Broker** | 仲介役 | メッセージの受け渡しを担う製品（RabbitMQ等） |
| **Producer** | 作る側 | Jobやイベントを作ってQueueへ送る |
| **Consumer** | 受け取る側 | Queueからメッセージを受け取る |
| **Worker** | 実行する側 | 実際にJobを処理するプロセス |
| **Batch** | まとめて処理 | 大量データ・大量Jobを一括で扱う方式（意味は文脈次第） |
| **排他制御** | 同時に触らせない | 競合を防ぐ**考え方**。ロックはその実装のひとつ |
| **ロック** | 鍵をかける | 特定の資源を占有する仕組み |
| **Mutex** | プロセス内の鍵 | 同一プロセス内の排他。プロセスはまたげない |
| **分散ロック** | プロセス外の鍵 | Redis等を使い、サーバーをまたいで排他する |
| **Transaction** | ひとまとまり | 全部成功か、全部なかったことにするか |
| **COMMIT** | 確定する | ここまでの変更を確定する |
| **ROLLBACK** | 取り消す | 今回の変更を取り消す |
| **分離レベル** | どう見えるか | 同時実行中のトランザクションが互いをどう見るか |
| **冪等性** | 何回でも同じ | 複数回実行されても結果が壊れない性質 |
| **At-least-once** | 最低1回 | 重複の可能性がある配信保証。多くのQueueの標準 |
| **DLQ** | 失敗の退避先 | Dead Letter Queue。何度も失敗したJobを隔離する場所 |
